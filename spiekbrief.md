# Spiekbrief Git en GitHub, versie van de website

## 1. Clone, commit, push en pull

clone: Hiermee download je een project voor het eerst van GitHub naar je eigen computer, zodat je eraan kunt werken.

commit: Hiermee sla je jouw aanpassingen lokaal op als een soort savegame, met een kort berichtje over wat je hebt veranderd.

push: Hiermee stuur je jouw opgeslagen aanpassingen door naar GitHub, zodat ze online staan en je teamgenoten ze kunnen zien.

pull: Hiermee haal je de nieuwste aanpassingen van je teamgenoten van GitHub binnen naar jouw eigen computer.


## 2. Een goed commitbericht

goed:
Spiekbrief: uitleg over .gitignore toegevoegd

slecht:
update (of aanpassingen)

waarom deze beter is:
Zo ziet een teamgenoot meteen welk bestand je hebt aangepast en wat er nieuw is, zonder dat hij alles eerst hoeft te openen. Dat maakt het later ook veel makkelijker om een foutje terug te zoeken of ongedaan te maken.



## 3. Gitignore

.gitignore is gewoon een simpel tekstbestandje in je projectmap waarin je een lijstje maakt van bestanden en mappen


## 4. Pull

Ik heb net online op GitHub de README aangepast en die verandering daarna met git pull binnengehaald op mijn eigen computer.

Aan het begin van elke les doe ik daarom eerst een pull, zodat ik meteen in de nieuwste versie werk en geen fouten of foutmeldingen krijg.


## 5. Terugdraaien

Git werkt gelijk een log boek dus alles van je geschiedenis blijft staan.


## 6. Branches en pull requests

Branch: Een aparte zijweg of kopie waarin je veilig iets nieuws bouwt, zonder aan je echte code te zitten.

Main: Blijft altijd de werkende versie, omdat je nieuwe dingen pas samenvoegt als ze echt af zijn en werken.

Pull request: Een verzoek om jouw nieuwe branch te checken en samen te voegen met de hoofdversie.
